## Le problème : qui est où, et quand ?

Le service après-vente de Weinmann Technologies organisait les interventions des techniciens dans des fichiers Excel. Des versions obsolètes qui circulent, des formules qui cassent, et surtout aucune vue lisible pour répondre à une question simple : **où est chaque technicien cette semaine ?**

## Une vue « ressources », pas un calendrier

Un calendrier classique montre des événements. Le SAV avait besoin de voir des **personnes**. J'ai donc construit l'interface autour du Scheduler de DayPilot en vue ressources :

- **une colonne par technicien**, l'échelle horaire en lignes ;
- les interventions se déplacent par **glisser-déposer** ;
- on voit d'un coup d'œil les trous, les chevauchements et les tournées.

Sur tablette, le glisser-déposer n'est pas natif au tactile : il a fallu adapter les interactions pour que le planning reste manipulable au doigt.

## Une API taillée pour le planning

Afficher plusieurs jours de planning pour toute une équipe, c'est beaucoup de requêtes si l'API est naïve. Le back-end Express expose une **API REST pensée pour les plages de plusieurs jours**, pour que l'affichage reste rapide quand on fait défiler la semaine, même avec une vingtaine de techniciens sur plusieurs semaines.

## Sortir d'Excel sans perdre l'historique

Le schéma MySQL a été conçu proprement dès le départ, et des **scripts de migration** ont repris les données existantes depuis les exports Excel.

## Mise en production

Déploiement sur serveur avec **PM2** pour garder les processus en vie, et **Nginx** en reverse-proxy pour le SSL et la gestion des sous-domaines.

<Callout title="Résultat">
La V1 a été adoptée par toute l'équipe SAV, sur ordinateur comme sur tablette. Les erreurs liées aux formules Excel ont disparu.
</Callout>
